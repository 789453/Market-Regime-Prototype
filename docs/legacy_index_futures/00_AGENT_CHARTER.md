## 1. 项目目标（以及一个必须先接受的现实）

### 1.1 名义目标

在 5 个股指期货（ES / NQ / RTY / HSI / HTI）的半年 1 分钟 OHLCV 数据上，构建一套**基于形态识别、状态调制的中频时序 CTA 系统**，目标持仓周期在 1–8 小时量级，日均开仓 1–4 次。

### 1.2 真实目标（更重要）

先把数学摆出来。夏普估计量的渐近标准误为

\[
\mathrm{se}(\widehat{SR}) \approx \sqrt{\frac{1 + \widehat{SR}^{2}/2}{T}}
\]

其中 \(T\) 为以年计的有效样本长度。本项目 \(T_{\text{cal}} = 0.5\) 年。跨品种池化能把它放大 \(N_{\text{eff}}\) 倍，而

\[
N_{\text{eff}} \approx \frac{N}{1 + (N-1)\bar\rho}
\]

由于（见第 3 节数据事实）HSI/HTI 只有夜盘、且夜盘时段与欧美盘完全重叠，五个品种的两两相关性显著高于最初预期：ES-NQ-RTY 之间约 0.80–0.90，HSI-HTI 之间约 0.90+，两组之间在重叠时段约 0.45–0.60。据此 \(N_{\text{eff}} \approx 1.3\text{–}1.6\)，取 1.45：

\[
T_{\text{eff}} = 0.5 \times 1.45 \approx 0.73 \text{ 年}
\quad\Rightarrow\quad
\mathrm{se}(\widehat{SR}) \approx 1.2
\]

**结论：本数据集上，只有真实夏普 ≥ 2.4 的策略才能达到 \(t = 2\)。**低于此的策略在统计上与噪音不可区分。

因此本项目的真实目标不是"跑出一个高夏普回测"，而是：

- **A. 建成一套可复用、无前视、可扩展的研究基础设施**（数据层、状态引擎、检测器框架、零分布框架、回测引擎）。这部分的价值不依赖于样本量，是本项目最确定的产出。
- **B. 产出一份"机制候选清单"**：对每个候选形态给出机制假说、效应量点估计、不确定性区间、跨品种符号一致性、参数邻域稳定性。目标是**筛掉大部分、保留少数**，而非证明少数。
- **C. 明确记录"数据不足以判断"的结论**。当 \(\hat\tau^2 = 0\)（格间无真实差异）或效应落在零分布的 60 分位时，如实写入报告并停止该分支。**这是合格产出，不是失败。**
- **D. 给出"当数据增加到 2 年/5 年时，哪些结论会被优先重新检验"的清单。**

> **禁止行为 #1**：为了让最终报告"好看"而放宽第 2 节的任何门槛。如果所有形态都没过门槛，正确的最终交付物是一份写明"在当前数据条件下未能识别出统计上可区分于噪音的形态，以下是基础设施与阴性结果记录"的报告。

### 1.3 明确的非目标

- 不做截面选股/选品种（仅时序）
- 不做宏观、基本面、期权、持仓报告等外部数据接入（当前无数据）
- 不做高频（< 5 分钟持仓）、不做做市、不做套利
- 不追求实盘级别的下单/风控代码，只需回测级别的忠实模拟
- 不做深度学习、不做遗传算法搜索形态

## 2. 反过拟合宪法（十条硬约束）

以下条款在整个项目生命周期内有效，任何模块的实现都必须遵守。每条后面括号里是自查方式。

1. **分母是有效下注数，不是数据行数。** 任何统计显著性论断必须基于独立下注数而非 bar 数。（自查：报告中出现 `n=136087` 这类数字作为统计依据时，立即改为触发次数。）

2. **禁止在原始价格上做任何全局参数拟合。** 所有特征必须先经波动率标准化与日内季节性剥离。（自查：搜索代码中是否存在直接用 `close` 差分做建模输入的地方。）

3. **所有形态与因子必须尺度不变。** 禁止出现绝对点数阈值、绝对成交量阈值、固定百分比阈值。允许：波动率倍数、经验分位、比值、序数关系。（自查：grep 代码中的魔法数字，每一个都必须能回答"它的量纲是什么"。）

4. **默认跨品种共享参数。** 品种特异参数需要显式论证并记录在 `RESEARCH_LOG.md`。唯一默认允许品种特异的量：成本、最小跳动、交易时段、无交易带宽度。（自查：参数表里 `per_instrument=True` 的条目数应 ≤ 5。）

5. **结构可以复杂，参数必须受约束。** 允许非线性、阈值、交互；禁止自由参数。每个参数必须来自：经济学先验、跨品种共享、分层收缩、或单调/符号约束。有效自由度定义为

   \[
   df_{\text{eff}} = \frac{1}{\sigma^{2}}\sum_{i=1}^{n}\mathrm{Cov}(\hat y_i,\, y_i)
   \]

   目标：最终系统 \(df_{\text{eff}} \le 15\)。（自查：用 bootstrap 数值估计 \(df_{\text{eff}}\)。）

6. **Regime 用于调制，不用于切换。** 禁止 `if regime == A: model_A else: model_B` 形态的代码。状态只能通过一个平滑、单调、低维的调制函数 \(g(\mathbf{c}_t) \in [0, 1.5]\) 作用于基础仓位。（自查：grep 代码中对 regime 变量的分支判断。）

7. **邻域稳定性优先于样本外。** 任何参数的选定必须先画出参数曲面。取高原中心，不取峰值点。稳定性指标

   \[
   \mathrm{Stab} = \frac{\mathrm{median}\{\text{邻域内表现}\}}{\text{峰值表现}} \ge 0.70
   \]

   （自查：每个入选形态必须有一张参数曲面图存档。）

8. **强制记录搜索次数。** 每一次参数网格扫描、每一次形态变体尝试（含被口头否决的），必须写入 `RESEARCH_LOG.md` 的试验计数器 \(K\)。最终夏普必须用 Deflated Sharpe Ratio 折算：

   \[
   SR_0 = \mathrm{se}(\widehat{SR})\cdot\Big[(1-\gamma)\,\Phi^{-1}\!\big(1-\tfrac{1}{K}\big) + \gamma\,\Phi^{-1}\!\big(1-\tfrac{1}{Ke}\big)\Big]
   \]

   （\(\gamma \approx 0.5772\) 为 Euler-Mascheroni 常数。）（自查：报告首页必须有 \(K\) 和 \(SR_0\)。）

9. **假设先行。** 编写任何检测器之前，必须先在 `HYPOTHESES.md` 中写下：机制假说（什么资金流）→ 预期在数据上的印记 → 预期方向 → 预期适用状态 → 预期失效条件。**先写假设，再看数据。**（自查：每个 detector 的 docstring 必须引用对应假设编号。）

10. **成本按实测的 1.5 倍计入。** 若策略在 1.0 倍成本下勉强为正，视为不工作。（自查：回测配置中 `cost_multiplier: 1.5` 不可修改。）

## 3. 数据事实（P0 已知/待验证清单）

以下事实已从分层样本中推断，**Agent 必须在 Stage 1 用全量数据逐条验证并写入 `reports/01_data_forensics.md`**。若验证结果与此处不符，以实测为准，并在 `RESEARCH_LOG.md` 中记录偏差与后续设计调整。

| 编号 | 事实 | 置信度 | 若成立的设计后果 |
|---|---|---|---|
| F1 | 时间戳为 UTC，且 ES/NQ/RTY 的会话边界随美国夏令时移动（`ESH6` 首 bar 23:00 UTC，`ESU6` 首 bar 22:00 UTC） | 高 | **必须用 tz 数据库转换为交易所本地时间**，禁止固定偏移。否则 3/1–3/8 这一周的日内季节性会整体错位 1 小时 |
| F2 | **HSI/HTI 仅含夜盘（T+1 时段）**，UTC 09:00–18:59 = HKT 17:00–02:59 | 很高 | 港股开盘 gap 类形态全部失效；HSI/HTI 与美股是**同步**而非隔夜关系 |
| F3 | HKEX 夜盘开始时间在样本中途从 17:15 改为 17:00（`HSIN6` 首 bar 09:15 UTC，`HSIQ6` 首 bar 09:00 UTC） | 高 | 会话日历必须**按合约/按日期分段**定义，不能全样本统一 |
| F4 | 存在 `volume=0, bar_count=0` 且 OHLC 全等的"网格填充 bar" | 高 | 必须建立 valid-bar 掩码；这些 bar 若进入 RV 会低估波动、若进入收益序列会制造虚假自相关 |
| F5 | ES/NQ/RTY 行数完全相同（136,087），共用同一时间网格 | 高 | RTY 在流动性差时段的 bar 大量为填充；RTY 的 valid 比例会显著低于 ES |
| F6 | 相邻合约之间**无重叠报价**（`ESM6` 末 bar 06-12 20:59，`ESU6` 首 bar 06-14 22:00） | 高 | **无法从数据中分离展期价差与周末跳空 ⇒ 不做后复权**，改为合约内计算收益、跨合约边界置 NaN |
| F7 | HTI 相对跳动 ≈ 2.13 bp（1/4700），是 HSI（0.39 bp）的 5.4 倍 | 高 | HTI 中频不可交易，降级为 context-only |
| F8 | HSI/HTI 夜盘单分钟成交量常在个位数至几十 | 高 | 夜盘点差宽、冲击大；HSI 需单独的成本曲线与更长持仓期 |

### 3.1 品种分层（基于 F2/F7/F8）

| Tier | 品种 | 角色 | 目标持仓期 |
|---|---|---|---|
| **A（主交易）** | ES, NQ, RTY | 信号生成 + 实际交易 + 统计池化主体 | ES/NQ 1–4h，RTY 3–8h |
| **B（次交易，条件性）** | HSI | 仅当其单独统计通过门槛才交易 | 6–16h |
| **C（仅 context）** | HTI | 不交易。用作 HSI 的确认变量、港股科技板块风险偏好代理 | — |

> Tier B/C 的判定不是先验的，是基于成本-波动比的数学推论：\(h^{\*} \propto (c/(\rho\sigma))^{2}\)。Agent 在 Stage 1 完成成本估计后必须重新核算此表并记录。

### 4.2 依赖

`python>=3.11`, `pandas>=2.1`, `numpy`, `pyarrow`, `scipy`, `statsmodels`, `numba`（可选，用于 ZigZag 与 bootstrap 加速）, `matplotlib`, `pyyaml`, `pytest`。

**不要引入 sklearn 以外的 ML 库。sklearn 仅允许用于：`IsotonicRegression`（单调约束）、`KMeans`（探索性聚类）、`GroupKFold`。禁止 GBDT/RF/NN。**

### 4.3 数据契约（模块间接口）

所有中间产物统一为 parquet，索引为 `(root, timestamp)`，`timestamp` 为 tz-aware UTC。

**`interim/bars_5m.parquet`**
```
root, timestamp, local_symbol, contract_con_id,
open, high, low, close, wap, volume, bar_count,
n_valid_1m,        # 该 5min 内有效 1min bar 数（0-5）
is_valid,          # bool: n_valid_1m >= 2
session_id,        # 交易日标识（按交易所本地日历）
session_phase,     # 时段分桶标签
bar_in_session,    # 该 bar 在会话中的序号
is_roll_boundary   # bool
```

**`processed/context.parquet`**
```
root, timestamp,
sigma_hat,         # 该 bar 的条件收益标准差（未年化）
sigma_day,         # 当日会话级波动预测
seas,              # 日内季节性乘子
sigma_pct,         # sigma_day 在过去 60 会话的分位 [0,1]
vol_ratio,         # sigma_fast / sigma_slow
er_20, er_60,      # 效率比
vr_5,              # variance ratio
liq_z,             # 流动性 z 分数
spread_bp,         # 估计有效点差 (bp)
avg_trade_size,    # volume / bar_count
es_ret_z,          # ES 同步标准化收益（跨市场用）
gate_score         # 状态调制得分 [0,1]
```

**`processed/labels.parquet`**
```
root, timestamp,
fwd_ret_{h}, fwd_ret_z_{h}   # h ∈ {6, 12, 24, 48, 96} 个 5min bar
                              # = 30min, 1h, 2h, 4h, 8h
label_valid_{h}               # 标签窗口是否跨越 roll / 会话缺口
```

**检测器输出 `processed/signals_{detector_id}.parquet`**
```
root, timestamp,
direction,   # -1 / 0 / +1
magnitude,   # 标准化强度，[0,1]
horizon,     # 建议持有期（bar 数）
confidence,  # 后验置信度 [0,1]，来自分层收缩
meta_*       # 该检测器的中间量，用于诊断
```

### 4.4 确定性与可复现

- 所有随机操作必须接收 `configs/base.yaml` 中的 `seed`
- bootstrap 的 seed = `hash(detector_id + stage_name) % 2**31`，写入日志
- 每个 stage 脚本以 `python -m src.stages.stage_N` 形式运行，可独立重跑
- 中间产物带 `_manifest.json`：记录输入文件 hash、配置 hash、生成时间、代码 git hash

## 5. Stage 门禁（Gate）与推进流程

Agent 按 Stage 顺序推进。**每个 Stage 结束必须产出 `reports/0N_*.md` 并更新 `STATE.md`，通过门禁才能进入下一 Stage。**门禁不通过时，不得跳过，必须回到本 Stage 修正或在 `DECISIONS.md` 中记录降级方案。

### Stage 0 · 环境与骨架
- 建立目录结构、配置文件、日志文件三件套（`STATE.md` / `RESEARCH_LOG.md` / `HYPOTHESES.md`）
- 加载 parquet，打印 schema，与文档 00 第 3 节逐条比对
- **门禁 G0**：`io_layer.load()` 能返回 494,035 行、5 品种、23 合约，字段与文档一致

### Stage 1 · 数据取证与清洗（文档 01 第 1–4 节）
- 执行 P0 校验清单全部 12 项
- 建立会话日历、valid-bar 掩码、5min bar
- **门禁 G1**：
  - F1–F8 全部有明确验证结论（成立/不成立/无法判定）
  - `bars_5m` 的 `is_valid` 比例：ES ≥ 70%，HSI ≥ 55%（若显著低于，先排查再继续）
  - roll 边界数 = 22（3 品种各 2 + 2 品种各 6 = 18… 以实测为准并记录）
  - 通过 `tests/test_no_lookahead.py::test_calendar` 与 `test_roll_boundary_nan`

### Stage 2 · 状态引擎（文档 01 第 5–7 节）
- 波动率估计、日内季节性、context 变量
- **门禁 G2**：
  - HAR 对 \(\log \sigma^2_{t+1}\) 的**扩展窗口样本外** \(R^2 \ge 0.40\)（ES/NQ）
  - 标准化收益 \(\tilde r = r/\hat\sigma\) 的日内绝对值均值曲线接近水平（剥离前后对比图必须存档；剥离后曲线的极差 / 均值 < 0.25）
  - \(\tilde r\) 的峰度显著低于原始收益（证明标准化生效）
  - 无前视断言通过：`sigma_hat[t]` 的计算仅使用 `t` 及之前的数据

### Stage 3 · 检测器与单形态统计（文档 02）
- 实现 `HYPOTHESES.md` 中全部假设对应的检测器
- 逐个产出统计卡片、零分布、参数曲面
- **门禁 G3**：至少 3 个检测器同时满足
  - 池化触发次数 ≥ 150，且至少 3 个品种各 ≥ 25
  - 跨品种符号一致：Tier A 三个品种中至少 2 个同号
  - 参数邻域稳定性 \(\mathrm{Stab} \ge 0.70\)
  - 在随机时点对照组的零分布中位于 ≥ 92.5 分位（单边）
  - 扣 1.5 倍成本后条件均值仍 > 0
- **若不足 3 个：不放宽标准。**回到 `HYPOTHESES.md` 重新思考机制，或如实记录阴性结论并进入 Stage 4 用现有检测器走完流程（此时最终报告定性为"基础设施交付 + 阴性结果"）

### Stage 4 · 状态条件化（文档 02 第 7 节）
- 对通过的检测器做状态分层统计与经验贝叶斯收缩
- **门禁 G4**：条件收益关于 `gate_score` 的曲线**单调且平滑**（用 isotonic 拟合的 \(R^2 \ge 0.6\)，且相邻分位间跳变 < 总幅度的 40%）。若为锯齿状，判定为噪音，退回无条件版本

### Stage 5 · 融合、仓位、回测（文档 03）
- **门禁 G5**：
  - 组合夏普 > 最优单检测器夏普 × 1.15（否则说明检测器冗余，回 Stage 3 增加机制多样性）
  - 成本 / 毛收益 < 35%
  - 前视注入测试全部通过（见文档 03 第 8 节）
  - 收益打乱测试：把信号随机平移 100 次，真实夏普位于分布 ≥ 95 分位

### Stage 6 · 自查、可视化、交付
- 完整审计清单、全部图表、最终报告

## 7. Agent 行为准则

1. **每个 Stage 开始前**：重读 `STATE.md` 与本 Stage 对应的文档章节。
2. **写代码前**：先写该模块的 pytest 断言（尤其是无前视断言）。
3. **遇到与文档不符的数据事实**：不要静默适配。写入 `RESEARCH_LOG.md`，评估对下游设计的影响，必要时在 `DECISIONS.md` 记录设计调整。
4. **遇到不确定的建模选择**：不要选"看起来结果更好"的那个。选**先验上更保守、参数更少、更可解释**的那个，并记录。
5. **不要过度防御**：允许合理假设、允许 fail fast。不要为每个函数写十层 try-except，不要为不可能的输入写分支。数据是干净的静态文件，不是生产流。**代码应该在假设被违反时崩溃，而不是静默兜底。**
6. **不要重复造轮子**：pandas/numpy/statsmodels 有的就用。但**波动率估计、ZigZag、bootstrap、回测循环必须自己写**（第三方实现的细节假设不可控）。
7. **每完成一个 Stage**：生成报告 markdown + 图，更新 `STATE.md`，然后**停下来**向用户汇报关键发现与门禁结果，不要连续跨多个 Stage 静默推进。
8. **报告写作**：先结论后过程；数字必须带不确定性；不要用"显著提升""效果良好"这类无量纲的形容词。

## 8. 常见陷阱速查（编码时对照）

| 陷阱 | 症状 | 防御 |
|---|---|---|
| 日内季节性用全样本估 | 回测夏普异常高，尤其是开收盘时段 | 扩展窗口滚动估计，最小 20 个会话起步 |
| \(\hat\sigma_t\) 用了当期 bar | 波动大的 bar 自动获得小仓位，虚假降波 | 断言 `sigma_hat[t]` 只依赖 `[:t]` |
| 重叠标签直接算 t 统计 | t 值虚高 2–3 倍 | stationary bootstrap，块长 ≥ 5h |
| 填充 bar 进入 RV | 波动被低估，标准化后信号虚强 | valid 掩码贯穿所有计算 |
| 跨 roll 计算收益 | 出现 ±1% 以上的虚假单 bar 跳空 | roll 边界收益强制 NaN |
| 固定 UTC 偏移分时段 | 3/1–3/8 与其余样本错位 1 小时 | `zoneinfo` + 交易所日历 |
| 用 `close` 成交 | 高估收益约 0.3–0.8 bp/笔 | 信号在 t 收盘产生，成交在 t+1 开盘 + 滑点 |
| HSI/HTI 用美股时段分桶 | 时段变量完全无意义 | 每个 root 独立的会话相位定义 |
| 组合层未做波动定标 | 五品种高相关，组合波动远超目标 | EWMA 协方差 + 组合级定标 |
| 用样本内表现给检测器加权 | 最隐蔽的过拟合 | 融合层先用等权，加权方案必须走独立门禁 |
